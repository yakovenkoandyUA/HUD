## Позиціонування

**Не запускати як список фіч.** Не «спогади + фінанси + завдання + книги + фільми + рецепти...» — це виглядає як перевантажений органайзер.

**Стартове позиціонування:**
> **MIMIR — Memory OS for your life spaces.**

Він:
- збирає розрізнені частини життя
- організовує їх у Life Spaces
- допомагає бачити зв'язки між подіями, людьми, планами, фінансами та пам'яттю
- поступово стає провідником по власному життю

**Функції — докази ідеї, а не сама ідея.**

**Ключова проблема користувача:**
> Моє життя розкидане між нотатками, фотографіями, календарем, банківським застосунком, списками справ і пам'яттю.

**Обіцянка MIMIR:**
> Зібрати це в одну зрозумілу систему, яка пам'ятає контекст.

**Формула бренду:**
> *Thought finds the path. Memory gives it meaning. Drink deep.*

**Уточнення по маскоту:**
Термін «ментор твого життя» — завеликий. Точніше:
> *Провідник по твоїй пам'яті, просторах і рішеннях.*
Мімір не керує твоїм життям. Він допомагає не втрачати його контекст. Не help-бот і не Clippy у мантії.

## Модель запуску

### Етап 0 — Launch Readiness (перед будь-якою рекламою)

Має працювати:
- [ ] Реєстрація та відновлення доступу
- [ ] Onboarding через Life Spaces (доводить до першої цінності)
- [ ] Створення першого Space
- [ ] Створення першого Memory
- [ ] Мобільна версія (PWA без критичних помилок після перезавантаження)
- [ ] Базова аналітика
- [ ] Privacy Policy
- [ ] Видалення або експорт даних (✅ вже є `/profile/account`)
- [ ] Зрозуміла форма зворотного зв'язку

> Якщо onboarding не доводить до першої цінності — маркетинг лише швидше приведе людей до розчарування.

---

### Етап 1 — Pre-Launch

**Результат:**
- [ ] Лендінг (одна сильна сторінка на основному домені)
- [ ] Instagram (акаунт + 3 закріплені публікації)
- [ ] Зарезервовані назви в TikTok і YouTube
- [ ] Коротке продуктове відео (35–45 сек)
- [ ] Waitlist / форма бета-набору
- [ ] Перші 30–50 кандидатів у бету

> Два тижні контенту — це не запуск. Це перший pre-launch sprint, після якого починається закрита бета.

---

### Етап 2 — Закрита бета (контрольований набір)

**Головне питання:** Чи повертається людина до MIMIR після першого знайомства?

**Activation-подія:** Користувач створив Space → додав перший змістовний запис → зрозумів, навіщо повернутися.

**Збираємо:**
- де люди зупиняються
- що не розуміють
- які модулі реально використовують
- як самі описують продукт
- що змушує повернутися
- що викликає недовіру

---

### Етап 3 — Public Beta

Лише після виправлення onboarding і базових сценаріїв:
- [ ] Відкриваємо доступ з waitlist

- [ ] Реальні відгуки
- [ ] Product walkthrough
- [ ] Тестування платних тарифів
- [ ] Referral-механіка

## Лендінг

**Концепція:** Не енциклопедія продукту — одна сильна сторінка на основному домені. Окремий великий сайт не потрібен.

**5 задач лендінгу:**

| Задача | Що має побачити людина |
|--------|----------------------|
| Пояснити | Що таке MIMIR за 5–10 секунд |
| Відрізнити | Чому це не Notion, Todoist або щоденник |
| Довести | Реальні екрани та сценарії |
| Довіра | Хто бачить дані, приватність, контроль |
| Конвертувати | «Приєднатися до закритої бети» |

### Структура

**1. Hero**
```
MIMIR
Memory OS for your life spaces.

Збирай пам'ять, людей, події, плани й фінанси у простори власного життя.

[Приєднатися до закритої бети]  [Подивитися 45-секундне демо]

Thought finds the path. Memory gives it meaning. Drink deep.
```

**2. Проблема — Хаос**
Notes / Photos / Calendar / банківські витрати / task manager / фільми та книги / «десь у голові»

**3. Life Spaces**
Три зрозумілих приклади (не двадцять типів):
- Я
- Сім'я / пара
- Подорож або важливий проєкт

**4. Як працює MIMIR**
Один цикл: Створи Space → додавай події та пам'ять → MIMIR збирає контекст → повертайся осмислено.

**5. Реальний інтерфейс**
Не AI-мокапи. Справжній продукт:
- створення Space
- додавання Memory
- пов'язані люди, місця, витрати
- Yearbook або Timeline
- поява Міміра в релевантний момент

**6. Хто такий Мімір**
Не help-бот. Провідник по пам'яті та рішеннях.

**7. Приватність** *(критично для продукту з пам'яттю та фінансами)*
- хто бачить дані
- які дані зберігаються
- як працюють shared spaces
- чи можна експортувати й видалити
- що передається AI

**8. Форма в бету**
- Ім'я
- Email
- Що зараз використовують
- Який сценарій цікавить
- Згода на участь у тестуванні

> Повну таблицю тарифів на pre-launch лендінг не виносити, доки не зафіксовані AI-ліміти, собівартість і ostаточні entitlements.

## Instagram

**Роль:** Не просто «гарно розповідати про MIMIR». Перевірити:
- який біль найсильніше резонує
- яке формулювання люди розуміють
- що викликає бажання спробувати
- які сценарії найбільш цінні

**Три закріплені публікації:**
1. Що таке MIMIR
2. Як працюють Life Spaces
3. Запрошення в закриту бету

**Reels важливіші за статичну «красиву сітку»** (рекомендація Meta для нових профілів).

### Контентні напрями

| Напрям | Зміст |
|--------|-------|
| Проблема | Життя розкидане між різними застосунками |
| Продукт | Реальні екрани й один сценарій за публікацію |
| Філософія | Пам'ять, контекст, глибина, DRINK DEEP |
| Мімір | Характер і роль провідника |
| Розробка | Чому прийняті конкретні продуктові рішення |
| Бета | Запрошення, питання, результати тестування |

> Міфологія — оболонка, не суть. Якщо половина профілю говорить про криницю, Одіна й руни, а не про користь — люди вирішать що це гра або NFT.

### Контент-план: перші 14 днів (8 сильних матеріалів + Stories)

| День | Формат | Тема | Мета |
|------|--------|------|------|
| 1 | Reel 20–25с | «Твоє життя розкидане між 7 застосунками» | Позначити проблему |
| 2 | Carousel | Що таке Memory OS | Пояснити категорію |
| 3 | Stories | Опитування: де зберігаєте пам'ять, плани, витрати | Дослідження аудиторії |
| 4 | Reel з UI | Створення першого Life Space | Показати реальний продукт |
| 5 | Stories | Чому MIMIR — не task manager | Відмежуватися від конкурентів |
| 6 | Carousel | Один Space: люди, події, місця, пам'ять, витрати | Показати контекст |
| 7 | Reel | Хто такий Мімір і чому він не чат-бот | Розкрити маскота |
| 8 | Stories | Питання аудиторії та відповіді | Зібрати заперечення |
| 9 | Reel з UI | Як додати Memory і пов'язати зі Space | Product proof |
| 10 | Carousel | «Що MIMIR не намагається замінити» | Зменшити скепсис |
| 11 | Stories | Фрагменти процесу створення інтерфейсу | Довіра до розробки |
| 12 | Головний Reel | 35–45с презентація MIMIR | Основний launch asset |
| 13 | Carousel | Для кого перша бета | Кваліфікація аудиторії |
| 14 | Reel + Stories | Запрошення в закриту бету | Конверсія |

**Не робити:**
- мотиваційні цитати заради заповнення профілю
- фальшиві відгуки
- AI-зображення неіснуючих екранів
- довгі списки функцій
- обіцянки «MIMIR змінить твоє життя»
- публікації, де сенс зрозумілий лише нам

## Продуктове відео (головний Reel)

**Формат:** 35–45 секунд, вертикальне 9:16, українська озвучка, субтитри обов'язково.
**Склад:** 70% реального UI + 20% брендова анімація + 10% атмосферні AI-сцени.

### Сюжет

**0–4 с — Проблема**
Швидко змінюються: нотатки → фотографії → календар → витрати → списки → незавершені плани.
> *Твоє життя зберігається всюди. Крім одного місця.*

**4–9 с — Поява MIMIR**
Темрява, поверхня криниці, слабке світіння.
> *MIMIR збирає розрізнені частини життя у Life Spaces.*

**9–24 с — Продукт**
Реальний запис екрана: створення Space → додавання події → Memory → люди → фінанси → пов'язані елементи.

**24–34 с — Роль Міміра**
> *Він не вирішує за тебе. Він пам'ятає контекст, показує зв'язки й допомагає бачити шлях.*

**34–41 с — Позиціонування**
> *Thought finds the path. Memory gives it meaning.*

**41–45 с — CTA**
> *Приєднуйся до закритої бети. DRINK DEEP.*

### Стек для створення

| Компонент | Інструмент |
|-----------|-----------|
| Реальний UI | Запис екрана застосунку (без персональних даних) |
| Атмосферні сцени | Runway Gen-4 (image-to-video: вода в криниці, руни, Мімір) |
| Монтаж + субтитри | CapCut Desktop (або Canva для презентаційного формату) |
| Озвучка | Власний голос (довірливіше) або ElevenLabs українською |

> Не генерувати усе відео одним ШІ. Вийде ефектний, але неправдивий рекламний туман.

## Правильний порядок дій (від Джонні)

1. Фіксуємо launch-позиціонування
2. Визначаємо **один** головний сценарій продукту
3. Робимо структуру лендінгу
4. Записуємо реальний demo flow
5. На його основі — контент і головний Reel
6. Відкриваємо набір у закриту бету

> Першим практичним кроком — **launch brief MIMIR на одну сторінку:** аудиторія, проблема, обіцянка, основний сценарій, CTA, критерії готовності продукту.
