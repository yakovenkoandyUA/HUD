## Репозиціонування монетизації: від продуктивності до платформи цифрової пам'яті

> Статус: ✅ **Затверджено (2026-07-06).** Контекст і мотивація → [`BACKLOG.md`](BACKLOG.md) → "Стратегічний напрямок продукту — Цифрова пам'ять / Family OS".

### Продуктова теза

Поточна сітка (розділи 1–10 нижче) продає **ліміти**: кількість транзакцій, сканів, спогадів. Технічно це працює, але слабко як позиціонування — конкурує з Notion/Todoist на їхньому полі ("ще один продуктивний застосунок").

Нова теза: MIMIR продає **довготривалу пам'ять, сімейну безперервність і спільний архів життя** — емоційну цінність, не функціональні ліміти. Практично це означає: фічі, які створюють *накопичену* цінність з часом (Timeline за роки, Yearbook, спільний сімейний архів), стають головним аргументом для оплати — не "у тебе закінчились скани чеків".

Це не відміняє існуючий аналіз купівельної спроможності/конкурентів (розділ 1) чи технічні обмеження по вартості інфраструктури (розділ 4) — вони лишаються вірними фактами незалежно від того, як називаються тарифи.

### Назви тарифів — затверджено (Варіант A, ідентичність користувача)

| Тариф | Назва | Для кого |
|-------|-------|---------|
| FREE | Personal Starter | Нові користувачі, "спробувати" |
| PERSONAL | Personal Memory | Активний соло-користувач |
| COUPLE | Shared Life | Пара, 2 профілі |
| FAMILY | Family Archive | Сім'я, до 4-6 профілів |

Четвертий тариф **Couple** — структурна зміна, не перейменування. Технічно лягає на існуючу модель `FamilyLink` (pairwise-зв'язок) — Couple — саме те, як FamilyLink вже працює.

Річна знижка ~20%. **Family/399₴** — свідомо вище "комфортної" межі для середнього класу (150–300₴), але виправдано: цільова аудиторія — пари/сім'ї з IT-доходами або ті, хто сприймає сімейний архів як довготривалу цінність. Couple/249₴ займає цінову нішу старого Family-тарифу з меншим охопленням (2 замість 4 профілів).

### Feature gates

**FREE:**
- Базовий dashboard, спринт/задачі, обмежені фінанси/спогади/watchlist/рецепти, базовий mood tracker
- Family Timeline — тільки preview (без повної історії)
- Yearbook — недоступний (генерація)
- FamilyLink — тільки invite preview, без активного зв'язку

**PERSONAL / PRO:**
- Необмежене персональне використання, Personal Timeline, Personal Yearbook
- Квота сканера чеків + AI-асистента, всі теми, export даних, повний offline

**COUPLE:**
- 2 профілі, спільні спогади/watchlist/настрій/покупки/рецепти/планування
- Couple Timeline, Couple Yearbook, спільний Memory Engine

**FAMILY / HOME:**
- До 4-6 профілів, повний FamilyLink, Family Timeline, Family Yearbook
- Сімейний архів пам'яті, сімейна mood-карта, спільні місця/плани, вищі ліміти AI/сканера/фото

### Launch order (пропозиція)

1. Family Timeline — ✅ MVP вже реалізовано (без гейтів, відкрито всім) → див. BACKLOG.md
2. Personal Yearbook (deterministic stats, кеш в Mongo, без AI) — найдешевший наступний крок, бо реюзає Timeline-агрегацію
3. Billing prerequisites (нижче) — паралельно з кроком 2, не після
4. Couple-тариф — потребує рішення про структуру (чи дійсно 4 тарифи, чи Couple зайвий)
5. Family Yearbook + AI-наратив — останнє, бо найдорожче (Anthropic) і найскладніше тестувати (мульти-юзер дані)

### Billing implementation prerequisites

- В `User` моделі зараз **немає жодного subscription/tier поля** — тільки `f1Enabled` і `isVerified` (boolean feature flags, не billing). Це треба будувати з нуля, не розширювати.
- Все з розділу 6 нижче (export даних, ToS/Privacy, Paddle vs Stripe рішення) лишається в силі незалежно від того, яка сітка тарифів переможе.
- Перш ніж гейтити Timeline/Yearbook — вирішити, чи retrofit-ити ліміти на вже реалізований відкритий MVP, чи лишити Personal-рівень відкритим до запуску білінгу (рекомендація: друге — не ламати UX вже працюючої фічі заради недозрілої цінової моделі).

### Що лишається безкоштовним (retention) — без змін від чинної логіки

Mood tracker, dashboard, core CRUD (квести/покупки/рутини) — як і в розділі 4 нижче. Додатково в новій рамці: **Family Timeline preview** (не повна історія, але сам факт існування стрічки) — бо це "обличчя" нового позиціонування, ховати його повністю за paywall з першого дня суперечить меті показати цінність пам'яті.

### Що варто продавати, бо створює довгострокову цінність

Не сканування чи AI-токени як такі (це вартість інфраструктури, розділ 4) — а **накопичена глибина**: повна історія Timeline за роки (не тільки поточний рік), Yearbook generation/export, спільний Couple/Family архів, AI-наратив над deterministic-статистикою. Це цінність, що росте з часом використання — складніше скопіювати конкурентом і складніше від неї відмовитись (lock-in через накопичені спогади, не через штучний ліміт).

## 4. Аналіз: що обмежувати і чому

### Обмежувати через вартість інфраструктури
| Функція | Чому платна | Поріг у Free |
|---------|-------------|--------------|
| Сканер чеків | Anthropic Vision API = ~$0.01–0.03/скан | 3/місяць |
| AI-чат | API tokens = реальні гроші | 0 у Free |
| Фото спогадів | Cloudinary storage | 3 фото/спогад |
| Push нотифікації | VAPID + server overhead | ❌ у Free |

### Обмежувати через диференціацію (не вартість)
| Функція | Чому платна |
|---------|-------------|
| FamilyLink | Головна "соціальна" фіча, сильний апгрейд-стимул |
| F1 повний | Нішева фіча, high value для фанатів |
| Всі теми | Психологічно легко апгрейдитись "заради теми" |
| Export даних | GDPR, довіра — але цінно для Pro |

### НЕ обмежувати (важливо для retention)
- Кількість квестів, рутин, покупок — це core value
- Mood tracker — потрібен кожен день, обмеження вб'є звичку
- Dashboard — це "обличчя" продукту, має вражати всіх
- Базові фінанси (до 50 транзакцій — досить для більшості)

## 9. Ризики і як їх знизити

| Ризик | Вплив | Мітигація |
|-------|-------|-----------|
| "Занадто дорого для UA" | Низька конверсія | Early bird + річний план; порівняння "5 застосунків за ціну одного" |
| Stripe не доступний в UA (без ФОП/юр.особи) | Не можна приймати платежі | Реєстрація як ФОП або через Paddle (підтримує UA фізосіб) |
| Users не розуміють цінність Free | Churn | Сильний onboarding + empty states |
| AI costs ростуть | Маржа падає | Жорсткі ліміти + кешування відповідей |

### Важливо: Stripe в Україні
Stripe напряму **не підтримує** Ukraine як країну отримувача платежів (2025).
Варіанти:
1. **Paddle** — підтримує UA, бере ~5% комісії, але є legal entity Paddle
2. **LiqPay / Fondy** — UA платіжки, але без глобального охоплення
3. **Реєстрація ФОП** + Stripe через партнера (складніше)

**Рекомендація:** почати з **Paddle** — він же виступає Merchant of Record, що знімає VAT/податкові питання.

## 10. Резюме рекомендацій

1. **Сітка:** Free / Personal 149₴ / Couple 249₴ / Family 399₴ (затверджено 2026-07-06)
2. **Free tier:** щедрий по core features, обмежений по AI та соціальних фічах
3. **Платіжна система:** Paddle (не Stripe) для старту — підтримує UA фізосіб, бере VAT
4. **Теми:** one-time покупка паралельно з підпискою
5. **Beta users:** 3–6 міс безкоштовно + вічна early bird ціна
6. **Порядок launch:** спочатку Personal; Couple через 1-2 міс; Family через 3-4 міс після стабілізації
7. **Timeline/Yearbook гейтинг:** не ламати відкритий MVP до launch білінгу — залишити Personal-рівень відкритим, гейтити тільки при активному paywall
